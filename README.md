# Climate Action Task Force interactive presentation

The local web presentation is in `site/`. It is a buildless HTML/CSS/JavaScript
artifact with frozen JSON, Google Fonts with licensed local fallbacks, downloadable reports and
deterministic demonstrations. It makes no participant-side scanner runs and
collects no shared responses.

Open the [participant presentation](https://atniclimate.github.io/climate-action-taskforce/)
or the [presenter view](https://atniclimate.github.io/climate-action-taskforce/?mode=presenter).
The presentation is a developing resource; individual figures retain their source,
coverage and interpretation limits.

## Preview

Serve only `site/` for a local preview at:

- Participant view: <http://127.0.0.1:8765/>
- Presenter view: <http://127.0.0.1:8765/?mode=presenter>

If the preview has stopped, serve `site/` with a local HTTP server bound to
`127.0.0.1`. For example, from this project directory:

```text
python -m http.server 8765 --bind 127.0.0.1 --directory site
```

For automated background work on this Windows host, follow the encoded
PowerShell/cmd PTY route in `AGENTS.md`. Opening `index.html` directly as a
`file:` URL will not reliably load the local JSON modules.

Use Chapters for direct navigation, the bottom controls or Left/Right arrows
for presenter navigation, and the view toggle for the vertical participant
edition. Interactive walkthroughs start only when Play is selected. Discussion
notes save only when the participant selects Save on this device.

## Reports and evidence

`literature/` holds the generated assessment and plan-discovery PDF/HTML reports
and CSV tables. Deliberate identical copies are in `site/literature/`.
`site/data/` holds the public datasets and claim/source ledger.

`data/plan-discovery/metadata-sidecar.json` preserves reusable discovery metadata
and working evidence locally; `site/data/plans.json` is its participant projection.
Its schema needs an explicit mapping before any future plan-assessor
import. Original assignments remain unchanged. Raw search receipts, source
inventories, source hashes and rendering/check evidence stay under `work/`.

The project never equates public search failure with absent Tribal planning.
Risk indices, all-geography county losses, overlapping place context, historical
disaster costs and award obligations remain separate measures. See the reports
for versions, coverage, missingness and limits.

## Reproduce deliberate outputs

These scripts read source repositories; they do not modify them or run their
full pipelines. Use the host execution route from `AGENTS.md`.

```text
python scripts/prepare_risk_data.py
python scripts/prepare_context.py
python scripts/prepare_assets.py
python scripts/merge_plan_discovery.py --require-complete
python scripts/prepare_sources.py
python scripts/build_reports.py
```

Risk extraction uses pinned cached inputs. Context generation uses retained
primary-source files. Asset generation uses ReportLab and locally staged
`zxing-cpp` for QR verification. Reports use ReportLab and included font files.
These are authoring tools, not browser dependencies. Search result files contain
executed evidence and are not regenerated by the merge command.

## Publication boundary

GitHub Pages serves **only `site/`**, including `.nojekyll`, with `index.html`
at the artifact root. Relative links support the GitHub Pages project subpath.
The Pages workflow runs for changes to `site/**` or its own workflow file on
`main`; a README-only change does not trigger it.

Keep original materials, private planning and handoffs, working receipts and
source inventories outside the published artifact. Repository publication and
site deployment are separate actions; the workflow's existence does not authorize
future changes to either.
